# 2026-11-05: fixtures, AemiTOML strict, the first measurements

**Fixtures.** swift-ci 4837c2c has a `git` command: a repository at a pinned commit, fetched without history, checked by its hash,
copied into `.build/fixtures`. `.ci/action.json` fetches toml-test v2.2.0 (`ce08da1`) and the YAML test suite's `data` branch (`6ad3d2c`)
before the debug, release and address-sanitizer test jobs, and sets `AEMIHMMML_FIXTURES=required`, so a missing suite fails in CI
instead of skipping.

**What the siblings already solved** (ADR-0010, at the owner's request to look before writing): one SIMD UTF-8 pass and one control-byte
`ByteSet` pass up front (AemiMarkdown), so a string only stops at its quote, a backslash and a line ending (`firstIndexOfAny`); floats by
Clinger, Eisel-Lemire, then `Double(String)` (AemiJSON); keys hashed with the per-process seeded `Hasher` (AemiJSON's duplicate check),
because AemiInterner's `WyHash` is unseeded; an explicit frame stack (AemiJSON).

**AemiTOML, strict.** TOML 1.0 and 1.1. toml-test: every valid file of both lists reads to its JSON, every invalid file is refused
(1.0: 474 invalid, 1.1: 467), on macOS and Linux; a recovering parse never throws on any of them. The suite passed whole on its first run,
which proves nothing by itself, so: harness controls (a wrong integer, float, string, date, kind, key or count is reported; TOML 1.1's
additions are refused under 1.0 and read under 1.1), and two hand mutations (dotted keys extending any table: 3 invalid files accepted;
leading zeros allowed: 6), both caught. Robustness: every prefix of every suite file under 400 bytes in both policies, 20,000 random
inputs, 100,000 nested brackets (a limit diagnostic), 10,000-part dotted keys. The prefix test found a read past the end in a refactor
before it was committed.

**Measured** (`swift package --package-path Benchmarks benchmark`, ordo-one, as AemiJSON; p50; machine load average 86, so thread CPU
time and instructions are the figures to trust, wall clock is not):

| | AemiTOML parse | TOMLDecoder parse | AemiTOML read all | TOMLDecoder read all |
|---|---|---|---|---|
| cargo-lock, generated, 497 KB | 66 instr/B, 101 MB/s, 4.2 mallocs/KB | 50, 183, 12.4 | 117, 68, 39 | 165, 56, 68 |
| twitter.toml, 443 KB | 81, 78, 2.1 | 63, 147, 14.3 | 111, 64, 18 | 156, 46, 46 |
| canada.toml, 4.6 MB | 71, 135, 0.0 | 47, 177, 12.7 | 109, 87, 25 | 282, 35, 181 |

Reading every value, AemiTOML does 30 to 60 % fewer instructions and allocates two to seven times less. **Parsing alone it is slower
than TOMLDecoder** (25 to 50 % more instructions), and both are far from the plan's 500 MB/s. That is the next work, by profile, not guess:
the suspects are four or five SipHash runs per key (the key's hash, then the dictionary hashing that hash again, on find and on insert),
the token classifier's several passes over each bare value, and kernel calls for short strings.
