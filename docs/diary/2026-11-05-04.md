# 2026-11-05: TOML writes, and Codable

Phase 2's writer and coders (ADR-0011). `TOMLTree` and `TOMLTable` are the owned form; `TOMLWriter` writes one canonical TOML that
1.0 and 1.1 both read; `TOMLEncoder` builds a table through reference nodes and writes it; `TOMLDecoder` reads through the views.

toml-test's own runner now runs in CI: built with Go from the suite's pinned commit (its `go.sum` pins the runner's modules) and driven
through `Tools/TOMLTestAdapter`, it passes decoder, encoder and invalid halves for both versions. Until now the decoder half had been
run only in-process; the official runner agrees.

`RFC3339DateTime` had no Codable conformance, and a retroactive one here would have been a warning (an error with warnings as errors)
and AemiHMMML's alone, so it went into aemi (beb96ea): coded as its text, read back as the same kind.

Measured, then fixed: writing canada.toml first cost 215 M instructions and 99 K allocations, one per float, since
`Double.description` allocates past fifteen bytes. Moving to aemi's Ryu made it worse (328 M, 111 K), which pointed at the integer
writer: it reversed digits through `bytes[start...]`, and mutating that slice copied the output buffer every time. With the swap in
place: 141 M instructions, 20 allocations, about 660 MB/s. twitter.toml's 18-digit ids had the same cost through `String(Int64)`:
2,523 allocations, now 20. The encoder's tables scan up to eight keys instead of hashing (202 M to 166 M on the Cargo.lock).

Left in phase 2: the JSON projection and Foundation's `Date`, both in the umbrella product. Benchmarks are on a loaded machine
(load average 6 to 11); instruction counts are what the comparisons use.
