# 2026-11-06: YAML recovers (phase 6, step 1)

`YAMLOptions(policy: .recovering)` reads any bytes without a throw (ADR-0014). YAML's state (indentation, possible keys, flow
levels, open collections) is too entangled to resume mid-parse, so recovery repairs the text instead: a strict trial parse,
and at each error the broken region is blanked (spaces, line breaks kept, so offsets hold) up to the next line at the enclosing
indentation; then a strict parse over the repaired copy. Two errors are repaired where they stand. `description: Use this: when`
keeps its colon as text. In composition, a duplicate key keeps the last pair (pruned when the mapping closes, so it stays
linear), and an alias that cannot stand reads as null.

What the tests found on the way:

- A pass that blanks nothing loops forever: an error at the end of a file whose cause is an open flow collection earlier on.
  Every pass now blanks a byte at least, or drops the rest.
- An unterminated quote reports its error on the next line it swallows, so blanking from the error lost the sibling after it.
  Recovery now restarts where the quote, or the outermost open flow collection, began.
- "Kept as text" first fired after an anchor (`&a key: v`): the key is saved at the anchor, so `simpleKeyAllowed` is false while a
  key is pending. Ten valid suite cases read differently until the check also asked for no pending key.
- Unlinking a replaced key walked the mapping's list: quadratic in the number of duplicates. The pair is now marked, and pruned in
  one pass when the mapping closes.
- A first draft cost strict reading 4% (a throwaway scanner in every parser's initializer, and the recovery branch in the
  plain-scalar byte loop). Now it costs under 1%: events 127M → 128M instructions on the corpus, composition 324M → 327M.

Two corrections to earlier records. yaml-test-suite has 94 error cases, not 95: the count included the fixture's `tags/error`
directory. And the README's "fewer instructions per byte than libyaml and libfyaml" went with ADR-0012's withdrawn 105. AemiYAML
is at libyaml's 170, behind libfyaml's 142.

CI had been red since the TOML writer (1c64021): x86-64 Linux refuses `5e-324` as a literal, and the macOS runner has no Go
for toml-test. Both were fixed in 933f941.

## AemiFrontMatter (step 2)

The rules (ADR-0015) were read from the tools' code rather than their documentation: Jekyll's regular expression, Hugo's lexer,
Mermaid's regular expression (whose `\1` makes an indented head close at the same indent), ask's `DefinitionFile`. The default is
the strictest reading all of them accept, and each looser one is an option: leading blank lines (Hugo, ask), indented fences
(Mermaid), an unclosed head ending at its first blank line (ask). JSON heads need `"` or `}` after their `{`, so a page that
starts with `{{< shortcode >}}` is not taken for JSON, as it is in Hugo.

Streaming was the part worth a property. `---` at the end of a prefix may still become `----`, and a CR may still get its LF.
For every prefix of every fixture, the locator is undecided or open until it gives the final answer, and then it never changes.
The first run caught two prefixes reported as no head: an empty text and a blank line still being written.

A head is read in place: the content is parsed over a copy of the text up to the head's end, with the bytes before it blanked.
YAML values and diagnostics then carry offsets in the caller's text, with no shifting.

## AemiMarkdown and AemiMermaid (step 3)

AemiMarkdown f65c685: `MarkdownExtensions.frontMatter` (its ADR 0006), off by default. The head is one block, and while it is
undecided the lines wait, which needed `FrontMatterStream`: asking `locate` again for each arriving line would read the head
quadratically. The first draft kept the head's state inline, and the corpus benchmark showed +1.2 % instructions with the extension
off: the parser on origin is still copied by its non-mutating helpers, so every byte it grows is paid for in those copies. Boxed
behind one pointer, with `Int.max` as "undecided" so the line check is one comparison, it costs 0.2 to 0.5 %. Every one-byte edit of
15 texts was checked against a fresh parse, tape for tape. AemiMermaid 098aa79 reads its `---` head (title, config) instead of
skipping it.

## ask moves over (6b)

ask's definition reader is now `AemiFrontMatter` plus the recovering parsers, and its ~700 lines of parsers are gone (its ADR 0147).
What ask's tests asked for that YAML and TOML do not say became repairs here, each general enough for any reader:

- A repeated TOML key now keeps the last value in recovering mode, as ADR-0006 always said. AemiTOML had kept the first. The earlier
  value is retired (its `parent` set to -2, so no lookup finds it) and pruned in one pass. The fuzzer's new link check found a
  "duplicate" that was two different invalid-UTF-8 keys, both decoded to U+FFFD: the check, not the parser, was wrong.
- A tab in indentation reads as a space, and `[WIP] fix the thing` reads as text.
- Comments' places, opt-in (`recordsComments`), for ask's hints; `YAMLValue.scalarStyle`; `TOMLValue.isInline`.

The owner's 136 harness files (95 unique) read identically before and after: every field, hint, note and body length.

## Phase 5, and what was owed

- **YAMLEmitter** (ADR-0016): all 308 valid suite cases written read back to their events, styles included. 4,000 random strings
  in every style and place found the top-level block scalar's indentation indicator (it counts from 0, as the suite's parsers
  read it). The fuzzer found plain continuation lines refused too eagerly, and tags whose `%` escapes and UTF-8 the emitter
  escaped although the parser keeps them raw. A tag that only a shorthand's escapes can hold gets a `%TAG` handle.
- **One encoder** (ADR-0017): the Codable surface moved to the core as the decoder's had. TOML's encoder sits on it unchanged,
  and YAMLEncoder is a format of it. Integers past 64 bits now decode into `UInt64`.
- **YAML 1.1** (ADR-0018), opt-in: merge keys are alias nodes of the originals, so the alias limits bound them. An edit that missed
  its anchor left the corpus test out of the first commit, and my ADR said the corpus had Compose merges. It has almost none.
  Both were fixed in 7217fa8. `str.replace` without an assertion is how that happened.
- A `5e-324` literal came back in the encoder test and broke x86-64 Linux CI again.
- **TOMLTables.tla**: the table rules hold over 53,761 states, the control fails, and AemiTOML agrees with the model on all
  14,425 inputs.
- **litmus on AemiTOML**: 260 mutants. 206 killed, 21 crashed, 5 timed out, 22 survived, 2 uncovered, 4 unviable. The survivors
  were the sign of `-nan`, integer overflow in only the multiplication or only the addition, tables inside inline tables, CR LF in
  strings and comments, two messages, and the Codable paths of trees (all now tested in `TOMLEdgeTests`), and seven equivalent
  mutants, accepted with their reasons. The re-run left six. Two were overflow mutants my literals could not kill: their wrapped
  values were still out of range. `0x10000000000000000` wraps to 0, and kills them. Three were an inline table's
  `owner`/`closed` bookkeeping, which never decides anything: every way into an inline table is refused at the table itself,
  and the model, which has no such flag, agrees with the parser on all 14,425 inputs. It is removed rather than accepted.
- **toml++ differential** (ADR-0019): one disagreement in 9,735 inputs, which TOML's text settles in AemiTOML's favour.
- **Two regressions I had not measured** (ADR-0017, two amendments). Sharing made Codable generic over the format, and generic
  code that Codable reaches through type-erased boxes runs unspecialized. On Cargo.lock, TOML encoding went from 174M to 256M
  instructions and decoding from 154M to 215M. Both are concrete now: encoding is at 179M, and decoding at 134M once
  `decodeIfPresent` makes one lookup instead of three. `@inlinable` changed nothing. The benchmark against the commit before
  sharing is what found it, and it should have been run when the sharing landed.
- **White paper** (`docs/WHITE-PAPER.md`): the family's evidence rule, safety rule and documentation law (AemiRegex, AemiProtobuf), and
  sunset's iteration rules: nothing waits on CI, and long verification (litmus, the differential with mutations, long fuzzing) runs in CI on
  its own schedule, never in the local loop. I had broken that rule all day: litmus for 90 minutes locally, the differential locally,
  `sleep 420` waiting on CI. Two claims were checked before they went in. The parsers do not recurse; `TOMLWriter` does, under the depth
  limit. Only AddressSanitizer runs, so the paper names only that. The ADRs gain `status:`/`date:` front matter, the open work moves
  to `docs/roadmap/` (0001 to 0005), and AemiRegex's `DocumentationLayoutTests` enforce the layout. Broken once on purpose (a `finished`
  status, an ADR without front matter): both fired.
- **Long verification moved to CI** (roadmap 0001, 0002). The toml++ differential is a nightly swift-ci command (75217f5, ADR-0019
  amended). Mutations are seeded per file, and a list of known disagreements fails on an unlisted or unseen entry. The ADR-0019 case
  is kept as a canary input. It was broken on purpose on a smoke-sized input (682 inputs in 53 s, nearly all of it process spawns):
  unlisted it fails, listed it passes, listed but absent it fails. swift-ci gained a `mutation` command (fce0688, four tests seen
  red under hand mutations), and AemiHMMML runs litmus nightly over its four modules with it. Neither nightly job has run yet; the
  workflow's schedule has not fired since it was added, so the first results are owed.
- **YAML 1.1 timestamps** (ADR-0020, roadmap 0003): an instant under `yaml11`, with the text kept. A date alone is midnight UTC, as the
  type page says. Keys compare by instant: the first draft hashed and compared every timestamp key as payload 0, so any two would
  have been duplicates. A first round of hand mutations "passed" because the mutants did not compile (`will never be executed`)
  and the old binary ran. Redone with mutants that compile, two checks did not fire. One was a blank-before-the-end path that only
  a tagged, quoted scalar reaches; a test now covers it. The other is the key-equality branch, reached only on a hash collision;
  nightly litmus will judge it. dolly caught the date and time readers as clones, so they became one `fields(_:between:)`.
  The core schema is unchanged, so there was no benchmark.
- **YAML Codable benchmarks** (roadmap 0004): 400 generated Deployments, 302,672 bytes. AemiYAML takes 440M instructions and 143K
  allocations to decode (Yams 880M, 403K) and 557M and 185K to encode (Yams 1,928M, 784K). Setup refuses to measure unless both
  libraries read the list alike and AemiYAML's output reads back to it. At about 1,450 instructions per byte against 170 for
  events, composition and decoding are where YAML's time goes (roadmap 0005). The machine's load average was 295 during the run;
  instruction counts held steady, but wall time was fifteen times CPU time.
- **YAML faster, first pass** (roadmap 0005), profiled before each change with `sample` on a release driver. The resolver tried every
  plain scalar as null, bool, int and float against word lists built as `[String]` per call (10 % of composing). A byte table and
  byte words cut composition by 29 %. `YAMLNode` lost its `String?`-holding `YAMLScalar` and now copies as bytes (−4.5 %). Coding
  paths are built only when asked (−2.3 % on decode). A chunked key hasher moved nothing and was reverted. Against the parent
  commit: corpus composition 329M to 226M, Deployments decoding 440M to 347M, TOML's Cargo.lock decoding 134M to 122M.
- **AemiFormal's report on aemi** (the owner's note): aemi's `KeyedHash` was written for AemiHMMML's own profile (its doc cites
  issue #5), and TOML's key index uses it, but YAML still hashed keys with `Hasher`, one byte at a time. It does not now: corpus
  composition 226M to 214M. The report also asks whether anyone needs integers past 64 bits. YAML's core integers are unbounded;
  AemiHMMML keeps such integers as text and parses them into the requested type. A shared big integer would let `YAMLValue` give
  their value. The answer goes to the owner rather than into AemiFormal's file.
- **Benchmarks in CI** (swift-ci 500bb54). A `benchmark` command runs the ordo-one package at the commit before (a worktree named
  like the project, with fixtures linked) and here, on the same runner. Only instructions and allocations are compared, against
  tolerances declared in the benchmarks: 2 % and 1 % at the median. It runs on pushes that touch `Sources` or `Benchmarks`,
  nightly, and on dispatch. Broken on purpose locally: an unchanged tree is within its tolerances. Reverting be96fd3 on top
  fails it, on exactly the two benchmarks it slows (composition +5 %, Deployments decoding +2.4 %). The plugin reports an
  improvement as an error too, so swift-ci reads its message rather than its exit status.
