# 2026-11-06: YAML recovers (phase 6, step 1)

`YAMLOptions(policy: .recovering)` reads any bytes without a throw (ADR-0014). YAML's state (indentation, possible keys, flow
levels, open collections) is too entangled to resume mid-parse, so recovery repairs the text instead: a strict trial parse,
and at each error the broken region is blanked (spaces, line breaks kept, so offsets hold) up to the next line at the enclosing
indentation; then a strict parse over the repaired copy. Two errors are repaired where they stand. `description: Use this: when`
keeps its colon as text. In composition, a duplicate key keeps the last pair (pruned when the mapping closes, so it stays
linear), and an alias that cannot stand reads as null.

What the tests found on the way:

- A pass that blanks nothing loops forever: an error at the end of a file whose cause is an open flow collection earlier on.
  Every pass now blanks a byte at least, or drops the rest.
- An unterminated quote reports its error on the next line it swallows, so blanking from the error lost the sibling after it.
  Recovery now restarts where the quote, or the outermost open flow collection, began.
- "Kept as text" first fired after an anchor (`&a key: v`): the key is saved at the anchor, so `simpleKeyAllowed` is false while a
  key is pending. Ten valid suite cases read differently until the check also asked for no pending key.
- Unlinking a replaced key walked the mapping's list: quadratic in the number of duplicates. The pair is now marked, and pruned in
  one pass when the mapping closes.
- A first draft cost strict reading 4% (a throwaway scanner in every parser's initializer, and the recovery branch in the
  plain-scalar byte loop). Now it costs under 1%: events 127M → 128M instructions on the corpus, composition 324M → 327M.

Two corrections to earlier records. yaml-test-suite has 94 error cases, not 95: the count included the fixture's `tags/error`
directory. And the README's "fewer instructions per byte than libyaml and libfyaml" went with ADR-0012's withdrawn 105. AemiYAML
is at libyaml's 170, behind libfyaml's 142.
