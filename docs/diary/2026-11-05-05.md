# 2026-11-05: phase 0 closed — the corpus and the YAML bar

**The corpus** is seven public repositories at pinned commits, fetched by the `suites` command beside the conformance suites
(swift-ci's `git` fixtures: the commit is the integrity check, no script and no hash list to keep): GitHub's starter workflows,
Docker's awesome-compose, kubernetes/examples, the OpenAPI specification's examples, ripgrep and rustlings (Cargo manifests and
locks), and poetry (pyproject files, its lock, its fixtures). 37 MB on disk; 138 TOML files, 537 YAML files (753 KB).

Every TOML file reads under strict TOML 1.1, and written and read back is the same tree (`TOMLCorpusTests`): nothing to list as
refused.

**The YAML bar**, measured on the 537 files (CPU time, best of 20; instructions retired, `proc_pid_rusage`;
`Benchmarks/References/yaml_references.cpp` against Homebrew's libraries, and Yams in the ordo-one package; load average 8 to 10, so
the instruction counts are the figures to compare):

| | refused | MB/s | instructions per byte |
|---|---|---|---|
| libyaml 0.2.5, events | 0 | 68 | 170 |
| libfyaml 0.9.6, events | 0 | 64 | 142 |
| libfyaml 0.9.6, tree | 6 | 46 | 203 |
| rapidyaml 0.16.0, tree | 7 | 186 | 42 |
| Yams 6.2.2, `compose_all` (libyaml, Swift nodes) | | 6.8 | 1,440 (545 K allocations) |

The six files the tree builders refuse are Kubernetes examples with duplicate keys, which YAML 1.2 forbids: a strict composer
(phase 4) refuses them too, a recovering one keeps the last (ADR-0006). rapidyaml's seventh is a sequence used as a key, which its
trees cannot hold.

Phase 3's events have to beat libyaml's 170 instructions per byte to be worth having, and the plan's target is rapidyaml's speed.
ask's own parsers are not measured here: they read heads of a few hundred bytes, and their corpus (the owner's 147 files) is not
public; phase 6b compares on it.

## Later: phase 3, YAML events

`AemiYAML` (ADR-0012): a libyaml-shaped scanner and parser with YAML 1.2's rules. The first run of the suite failed 21 of 402
cases; the fixes, each from a failing case: a top-level block scalar's content may start at column 0 (M7A3, W4TN, DK3J, FP8R); `:`
after a JSON-like key also across lines (5MUD, K3WX); `[ : x ]` (CFD4); a comment after a reserved directive (2LFX, 6LVF); the
last line of a block scalar without its break (JEF9, L24T); tabs between block indicators and where a block scalar indents (the
nine Y79Y cases); and dropping a "`:` first on its line" rule that `- ? : x` showed was wrong once plain scalars stopped making
room for keys after their last line. All 402 pass, all 95 errors are refused, the ratchet is empty.

Events cost 105 instructions per byte on the corpus, 126 with every value decoded (libyaml 170); the one-line scalar read straight
from the source took the decoded figure from 183 to 126. Nothing crashes on any prefix of the suite's inputs or on random edits.
`hexValue`, written twice (TOML and YAML), is aemi's `Hex.value` now, and the TOML writer's hex digit `Hex.upperDigit`.

## Later: phase 3 closed

DEL, C1 controls and U+FFFE/U+FFFF are now refused outside quoted scalars. libFuzzer targets for both formats ran clean (5.3 M
YAML, 2.3 M TOML inputs on macOS; Linux too); two TLA+ models of the scanner, each with a refuted control and a paired Swift
oracle; the suite passes on Linux (ADR-0012's amendment).

Meanwhile the family's history was rewritten twice (identities and signatures corrected, so SHAs changed), and the first round's
pin corrections named commits whose own manifests still held the old SHAs: 20 repositories no longer resolved. My phase 3 commit
had also put AemiHMMML's old pins back over the first correction (its working copy still held them). The second round fixed the
manifests too; the cascade that followed, leaves first from current heads, repins the rest, and AemiHMMML now pins aemi e30aad8
and AemiJSON aec8895, a graph that resolves.
