# AemiHMMML — plan (accepted 2026-11-05)

Status: the owner accepted the plan and every recommendation in section 8 (2026-11-05), and added AemiMarkdown's front matter as a consumer.

AemiHMMML ("Aemi How Many More Markup Languages"): strict, fast, safe parsers and writers for YAML, TOML and the configuration
formats that follow, on the model of AemiJSON, AemiProtobuf, AemiMarkdown, AemiMermaid and AemiRegex. Criteria, in order: strict and
accurate conformance, high performance, safety, reliability, resilience.

## 3. What the family already gives us

- **AemiKernel**: `TapeSlot` (the shared 64-bit preorder tape that AemiJSON's tape is built on), `SWAR`, `ByteBitmap`, `ByteSearch`, `UTF8Validation`,
  `UTF8Decode`, `DecimalFloat` (Eisel-Lemire parse, Ryū shortest print), `NumberParse`, `CheckedMath` (TOML's 64-bit overflow rule), `WyHash`,
  `Hex`, `Base64` (YAML `!!binary`), `SparseSet`.
- **AemiKernels**: runtime-dispatched SIMD (NEON/SSE) — `indexOfControlOrAny`, byte sets, small byte sets, pair sets, UTF-8 — for skipping
  plain-scalar runs, comments and quoted strings in bulk.
- **AemiInterner / InternedStrings**: key interning for repeated keys (Kubernetes, CI files).
- **AemiUnicode / AemiText**: YAML's printable set and line breaks, line/column on demand.
- **AemiJSONCore** (Foundation-free): `JSONValue` and **JSON Schema** — a YAML or TOML document projected to JSON can be validated
  by the schemas we already have; toml-test's tagged JSON and the suite's `in.json` are compared through it.
- **AemiRegex**: not in the hot path (the YAML core schema's regular expressions are hand-written recognisers), but for schema `pattern`s.
- **AemiTestKit**: `Allocations`, `Fuzz`, `GuardedBytes`, `ConstrainedStack` (stack-depth tests), `SeededRNG`, `Oracles`, `Benchmarks`.
- **AemiMarkdown's model**: tape with byte offsets and no copies, streaming append, `MarkdownEditor` edits in time proportional to the edit, a
  spec ratchet that must end empty, a public corpus fetched by manifest with SHA-256, CPU-time and cycles-per-byte measurement.
- **AemiProtobuf's model**: a conformance runner in `Conformance/`, a `failure_list.txt`, `Models/` (TLA+ and Lean) each paired with an
  exhaustive Swift oracle test, fuzz executable, coverage floors.
- **swift-ci**: one `.ci/action.json`; fixture commands before tests; sanitizers (address, thread, undefined) on macOS and Linux; quality with
  swift-format, discipline (`strtod`, `untyped-throws`, `wall-clock`, force unwraps), deadwood, dolly, arcleak, fcheck, modeler; TLA+ runs;
  tool lock pinned by SHA. **litmus** for mutation testing.

## 4. Architecture

One repository `g-cqd/AemiHMMML`, MIT, Swift 6.4, strict concurrency and strict memory safety, macOS and Linux from day one (the cores are
Foundation-free, like AemiJSONCore). Products:

| Product | Content | Depends on |
|---|---|---|
| `AemiHMMMLCore` | Source buffer, byte positions → line/column on demand, `Diagnostic`, `Limits`, `ErrorPolicy`, date-time and number values, tape helpers | aemi (AemiKernel, AemiKernels, AemiUnicode) |
| `AemiTOML` | Lexer → tape; `TOMLDocument` lazy navigation; table-definition checker; canonical writer; 1.0 and 1.1 modes | Core |
| `AemiYAML` | Scanner → **event stream** (pull) → composer (tape with anchors, aliases, tags) → schema resolution → emitter | Core |
| `AemiFrontMatter` | The one locator of heads (`---` YAML, `+++` TOML, a leading JSON object), streaming-aware, and the parsed head | Core, TOML, YAML, AemiJSONCore |
| `AemiConfigLines` (later) | Line-oriented dialects with explicit specs: INI dialects, `.env`, properties, git-config, EditorConfig | Core |
| `AemiHMMML` (umbrella) | Foundation conveniences (`Data`, `Date`), Codable `TOMLDecoder`/`TOMLEncoder`/`YAMLDecoder`/`YAMLEncoder`, projection to `JSONValue`, format detection | all + AemiJSONCore |
| `hmmml` (executable) | `validate`, `convert`, `inspect`, `events` — like `aemi-proto-check` and `aemi-mermaid` | umbrella |
| `AemiHMMMLConformance` (executable) | toml-test decoder/encoder adapter (tagged JSON on stdio), yaml-test-suite runner | umbrella |
| `AemiHMMMLFuzz` (executable) | libFuzzer targets per format, plus differential targets | umbrella |

### Decisions to record as ADRs before code

1. **Strict by default, recovery as a mode.** `ErrorPolicy.strict` throws the first error with its byte position (the conformance mode).
   `ErrorPolicy.recovering` never throws: it returns what it read, skips to the next resynchronisation point (next line for TOML; the next line at
   or below the enclosing indentation for YAML), and lists diagnostics — exactly ask's ADR-0092 contract, so ask keeps its leniency on top of a
   conformant parser instead of a second grammar.
2. **Lossless tape, typed views.** The tape records every node by byte offset (no copies), its style (plain, single, double, literal, folded;
   TOML's four string forms; flow or block) and its source range. Typed values are resolved lazily, as in AemiJSON. A later concrete syntax
   layer (comments, whitespace) serves format-preserving edits (TOML like Rust's `toml_edit`, YAML like AemiMarkdown's editor).
3. **YAML schema is an option, never a guess**: `failsafe`, `json`, `core` (default, YAML 1.2.2 §10.3), and `yaml11` for compatibility
   (`yes/no/on/off` booleans, sexagesimal, merge keys `<<`) — opt-in and named, so the "Norway problem" and GitHub's `on:` key are explicit.
   Unknown tags are kept as data and **never construct a type**. Merge keys only with `yaml11` or an explicit option.
4. **Resource limits are part of the API** (`Limits`, all with safe defaults): document bytes (the tape's 32-bit offsets bound it at 4 GiB),
   depth, **alias expansion budget** (billion laughs), aliases per document, scalar bytes, keys per mapping, documents per stream. Iterative
   parsers with explicit stacks, no recursion on input depth (`ConstrainedStack` tests prove it). Linear time on every input, including duplicate
   key detection (seeded WyHash) and YAML's implicit keys (the spec's 1024-character limit is enforced, not merely tolerated).
5. **Duplicate keys are errors** in strict mode, in both formats (YAML 1.2 requires unique keys; complex keys compare by resolved value).
   Recovering mode keeps the last and reports it, as ask does today.
6. **Versions are explicit**: `TOMLVersion.v1_0 / .v1_1` (1.1 default), `YAMLVersion.v1_2` with the `%YAML` directive honoured and 1.1
   documents read under `yaml11` only when asked.
7. **Numbers and dates**: `DecimalFloat` for floats (no `strtod`, already a discipline rule), exact 64-bit integers with overflow as an error,
   TOML's four date-time kinds as Foundation-free value types with a `Date` bridge in the umbrella.
8. **The value model**: each format keeps its own document type (YAML has tags and anchors, TOML has date-times); both project into
   `JSONValue` with a documented, lossy-where-necessary mapping (the same one toml-test and the suite's `in.json` use).

### Front matter, and AemiMarkdown

- **One locator, in `AemiFrontMatter`.** It decides whether bytes start with a head and where it ends: an optional BOM, the opening fence on
  the first line (`---` YAML, `+++` TOML, `{` JSON), the closing fence (`---` or `...` for YAML, `+++` for TOML, the matching `}` for JSON),
  CRLF, trailing spaces on fences, a bound on head bytes. Rules written down in an ADR against the documented behaviour of Jekyll, Hugo,
  GitHub, Mermaid and the Agent Skills format, each rule with fixtures, since no specification covers front matter.
- **AemiMarkdown depends on `AemiFrontMatter`** (in-family, Foundation-free, no cycle: AemiHMMML never depends on AemiMarkdown). A new
  extension `MarkdownExtensions.frontMatter` (bit 7, the last free bit of the `UInt8` option set; widening it is part of the change) makes the
  head a block of its own at the start of the tape, with its byte range, format and parsed value. Off, CommonMark 0.31.2 and GFM
  conformance are unchanged (all 682 examples keep passing); `.github` gains it only if the owner wants GitHub's rendering by default.
- **Streaming and editing**: while the closing fence has not arrived, the head is provisional like AemiMarkdown's open block; once closed it is
  final. An edit inside the head re-reads the head only and reports one changed block (ADR-0003's contract). An unclosed head that grows past the
  bound falls back to Markdown, as an unterminated head does in ask today.
- **Errors**: AemiMarkdown never fails, so it parses heads with `ErrorPolicy.recovering` and exposes the diagnostics; strict reading stays
  available to callers that want it.
- **Renderers**: TerminalKitMarkdown and MarkdownLook choose to hide the head or show it as a table (as GitHub does).
- AemiMermaid uses the same locator for its `---` block and reads `title` and `config` from it; ask's `DefinitionFile` reads its heads
  through it instead of its own fence code; ask's and analyzerkit's DocumentationLayout tests read record front matter through it.

## 5. Verification (each phase must pass all of it before the next starts)

- **Conformance**: toml-test (decoder and encoder, 1.0 and 1.1 file lists) through the adapter; yaml-test-suite at the event level
  (`test.event`), the JSON level (`in.json`), error cases (`error`) and the emitter (`out.yaml`, `emit.yaml`). A ratchet file like
  AemiMarkdown's `SpecRatchet` and AemiProtobuf's `failure_list.txt`, which must be **empty** to close a phase. Suites fetched at pinned commits
  by a swift-ci fixtures command (as AemiJSON's `fetch-fixtures`); the toml-test binary pinned by SHA in swift-ci's tool lock, like TLC's jar.
- **Differential**: random and corpus inputs against rapidyaml/libfyaml (YAML) and toml++/TOMLDecoder (TOML), differences classified as in
  AemiMarkdown's `DifferentialTests`; ask's current `DefinitionFile` against the recovering mode on the owner's 147 files and ask's fixtures.
- **Property tests**: parse ∘ emit ∘ parse is the identity on the document; emit is deterministic; every byte string terminates in linear time
  under the limits; recovering mode never throws.
- **Fuzzing**: libFuzzer targets per format and per mode, under ASan/UBSan, with corpus seeding from the suites; a CPU-hour budget per phase.
- **Sanitizers** (address, thread, undefined) on macOS and Linux through swift-ci; allocation budgets per KB (`AemiTestKit.Allocations`).
- **Formal models where state is intricate**, each with a `.buggy.cfg` control and a paired Swift oracle test (AemiProtobuf's rule):
  TOML's table-definition rules (defined, implicitly defined, dotted-key-defined, array of tables, inline tables closed) exhaustively over
  small key paths; YAML's block indentation and simple-key stack. Lean for the small arithmetic lemmas (integer/underscore grammar, date ranges)
  only if they pay for themselves.
- **Quality**: swift-ci quality with discipline on (`strtod`, `untyped-throws`, `wall-clock`, force unwraps), deadwood, dolly, arcleak, fcheck,
  modeler; coverage floors; **litmus** mutation score with surviving mutants reviewed per phase.

## 6. Performance

- Method from AemiMarkdown and AemiJSON: release builds, CPU-time clocks, instructions and cycles per byte, allocations per KB, a public
  corpus fetched by manifest (GitHub workflows, Kubernetes manifests, Docker Compose, OpenAPI documents, `Cargo.toml`/`pyproject.toml`, the
  owner's harness files), and the reference parsers on the same machine.
- Techniques: SIMD classification of structural bytes per 16/64-byte block (AemiKernels) to skip plain scalars, comments and quoted runs;
  SWAR for short runs; no copies (tape of offsets, strings decoded lazily and only when they have escapes or folding); interned keys;
  reusable parser state (AemiMarkdown's 0.2 allocations/KB when reused); lazy typed access (AemiJSON's "read two fields, decode nothing else").
- Targets (hypotheses to confirm in phase 0): TOML ≥ 500 MB/s on configuration files; YAML block style at or above rapidyaml's ~200 MB/s
  parse; emit ≥ 300 MB/s; zero allocations per value on a reused parser. Each target gets a CI budget once measured, like ask's budgets.
